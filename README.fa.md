# دستیار هوشمند قانون کار ایران

[English](README.md) · [دموی آنلاین](https://laborlaw-rag.streamlit.app/)

یک دستیار فارسی مبتنی بر بازیابی افزوده (RAG) برای پاسخ‌گویی مستند به پرسش‌های قانون کار ایران است. سامانه پرسش کاربر را نرمال‌سازی می‌کند، مواد و تبصره‌های مرتبط را با بازیابی هیبریدی پیدا می‌کند و پاسخ نهایی را همراه با ارجاع‌های شماره‌دار ارائه می‌دهد.

## دموی آنلاین

نسخهٔ تحت وب پروژه از لینک زیر در دسترس است:

**[اجرای دستیار قانون کار](https://laborlaw-rag.streamlit.app/)**

## قابلیت‌ها

- پاسخ‌گویی فارسی بر پایهٔ مواد و تبصره‌های موجود در مجموعه‌داده
- بازیابی هیبریدی با ترکیب جست‌وجوی معنایی و واژگانی
- نرمال‌سازی اجباری پرسش‌های فارسی و پشتیبانی از عبارت‌های محاوره‌ای
- بازنویسی اختیاری پرسش برای بهبود بازیابی در پرسش‌های پیچیده
- درج ارجاع شماره‌دار پس از گزاره‌های حقوقی و نمایش فهرست منابع در انتهای پاسخ
- تفکیک پرسش نامرتبط از پرسش مرتبطی که شواهد کافی برای پاسخ آن وجود ندارد
- حافظهٔ محدود شش رفت‌وبرگشت اخیر برای فهم پرسش‌های پیرو و ارجاع به گفت‌وگوی قبلی
- پاسخ داخلی و بدون مصرف API برای احوال‌پرسی و معرفی دستیار
- جلوگیری از ارائهٔ پاسخ حقوقی بدون پشتوانهٔ منابع بازیابی‌شده
- رابط فارسی راست‌به‌چپ با فونت Vazirmatn، تاریخچهٔ گفتگو و امکان پاک‌کردن آن
- نمایش نام مدل و زمان کل پردازش در کنار هر پاسخ
- رابط‌های وب Streamlit و Gradio و API مبتنی بر FastAPI
- امکان افزودن منابع HTML، متنی و PDF با ساختار مشترک پردازش داده

## فرایند پاسخ‌گویی

```text
پرسش کاربر
  ← نرمال‌سازی فارسی
  ← رفع ارجاع با استفاده از حافظهٔ محدود گفتگو
  ← بازنویسی اختیاری پرسش
  ← بازیابی هیبریدی
  ← ادغام و رتبه‌بندی نتایج
  ← تولید پاسخ مبتنی بر شواهد
  ← اعتبارسنجی ارجاع‌ها و قالب‌بندی نهایی
```

سامانه سه نوع نتیجه تولید می‌کند:

- `answer`: منابع برای ارائهٔ پاسخ مستند کافی هستند.
- `insufficient`: پرسش در حوزهٔ قانون کار است، اما منابع موجود پاسخ کافی و صریحی ندارند.
- `out_of_scope`: پرسش خارج از حوزهٔ قانون کار است.

## راه‌اندازی محلی

پروژه از Python نسخهٔ 3.12 تا 3.14 پشتیبانی می‌کند.

```powershell
git clone https://github.com/amir-9473/laborlaw-rag-ir.git
cd laborlaw-rag-ir
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

کلیدهای زیر را در فایل `.env` وارد کنید:

```dotenv
JINA_API_KEY=your-jina-api-key
OPENROUTER_API_KEY=your-openrouter-api-key
LLM_MODEL=qwen/qwen3-8b
```

سپس رابط وب یا API را اجرا کنید:

```powershell
.\run_app.bat
.\run_api.bat
```

- رابط وب: `http://localhost:8501`
- مستندات API: `http://127.0.0.1:8000/docs`
- بررسی زنده‌بودن سرویس: `GET /health`
- بررسی آمادگی سرویس: `GET /ready`

در سیستم‌عامل‌های دیگر می‌توان از دستورهای زیر استفاده کرد:

```bash
python -m streamlit run streamlit_app.py
python app.py
python -m uvicorn laborlaw_rag.api:app --host 127.0.0.1 --port 8000
```

## استفاده از API

برای دریافت پاسخ، یک درخواست `POST` به مسیر `/v1/ask` ارسال کنید:

```json
{
  "question": "شرایط فسخ قرارداد کار چیست؟",
  "use_query_transformation": false,
  "conversation_history": [
    {"role": "user", "content": "قرارداد کار چیست؟"},
    {"role": "assistant", "content": "پاسخ قبلی دستیار"}
  ]
}
```

پاسخ API شامل وضعیت پاسخ، پرسش نرمال‌شده، متن نهایی، منابع، اطلاعات مدل و زمان‌بندی مراحل پردازش است.

## تنظیمات اصلی

| متغیر | کاربرد | مقدار پیش‌فرض |
|---|---|---|
| `JINA_API_KEY` | دسترسی به سرویس embedding و reranking | الزامی |
| `OPENROUTER_API_KEY` | دسترسی به مدل زبانی | الزامی |
| `LLM_MODEL` | مدل تولید پاسخ | `qwen/qwen3-8b` |
| `RAG_QUERY_TRANSFORMATION` | فعال‌سازی بازنویسی پرسش در سطح تنظیمات | `false` |
| `RAG_MEMORY_MAX_TURNS` | تعداد رفت‌وبرگشت‌های اخیر مورد استفاده برای حافظه | `6` |
| `RAG_MEMORY_MAX_CHARS` | سقف نویسه‌های تاریخچهٔ مورد استفاده برای رفع ارجاع | `6000` |
| `REQUEST_TIMEOUT` | مهلت درخواست‌های خارجی برحسب ثانیه | `90` |
| `DEMO_ACCESS_CODE` | رمز اختیاری برای محدودکردن دسترسی به دمو | بدون مقدار |
| `DEMO_MIN_REQUEST_INTERVAL` | حداقل فاصلهٔ بین دو پرسش در هر نشست | `3` |
| `DEMO_MAX_QUESTIONS` | حداکثر تعداد پرسش در هر نشست | `20` |

فایل‌های `.env` و `.streamlit/secrets.toml` حاوی اطلاعات محرمانه هستند و نباید در Git ثبت شوند.

راهنمای کامل استقرار و رفع اشکال Hugging Face Spaces در فایل
[`docs/huggingface-deployment.md`](docs/huggingface-deployment.md) قرار دارد.

## افزودن منبع جدید

لایهٔ دریافت و پردازش داده مستقل از پایپلاین پرسش‌وپاسخ است. برای افزودن یک وب‌سایت، فایل متنی یا PDF جدید، کافی است منبع در قالب ورودی مشترک پروژه ارائه شود؛ مراحل پارس، قطعه‌بندی، نمایه‌سازی و تولید ارجاع بدون تغییر در منطق اصلی قابل استفاده خواهند بود.

## تست و کنترل کیفیت

وابستگی‌های توسعه را نصب و بررسی‌های پروژه را اجرا کنید:

```powershell
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.venv\Scripts\python.exe -m ruff check src tests notebooks streamlit_app.py
.venv\Scripts\python.exe -m ruff format --check src tests notebooks streamlit_app.py
.venv\Scripts\python.exe -m pytest -m "not live"
```

تست‌های عادی بدون فراخوانی سرویس‌های خارجی اجرا می‌شوند. تست‌های متصل به APIها به‌صورت جداگانه و فقط با فعال‌سازی صریح اجرا می‌شوند تا مصرف سهمیه کنترل شود.

## منبع داده

مجموعه‌دادهٔ اصلی از [صفحهٔ قانون کار در وب‌سایت صلح](https://www.solh.ir/regulation/1/66) تهیه شده است. معماری پروژه امکان ترکیب این مجموعه با منابع معتبر دیگر را نیز فراهم می‌کند.
